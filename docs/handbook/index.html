    Overview

    What XP Notepad is

    Verified at runtimeOverview

    XP Notepad is an unofficial recreation of the Windows XP Notepad (Luna blue), written in GDScript for Godot 4.7.2. The window, caption, menu bar, dialogs and status bar are drawn by the engine. The project has no WebView, no HTML, no native code of its own and no add-on. It is not affiliated with Microsoft.

    Version 0.2.0 is a rewrite of the Flutter version (0.1.0 to 0.1.2). The behaviour of the menus, dialogs, shortcuts, encodings and settings is meant to be the same; the differences are listed under What changed from the Flutter version. It was built and run on Linux only: the test suite runs headless, the app was run under a virtual display (Xvfb), and the Linux and Windows x64 exports were built. Windows and macOS were not run, no screen reader has been tried, and the CI workflows have never run.

    Known differences and limits at a glance

    Verified at runtimeOverview

    • Printing. Print writes a PDF to the cache folder and opens it in the system's PDF viewer. There is no native print dialog (see Print).
    • NUL characters and lone UTF-16 surrogates. A Godot string cannot hold either. A NUL in a file is read as a space and a lone surrogate as U+FFFD, so saving such a file writes those characters back (see Encodings and line endings).
    • Tab. A tab is drawn 8 columns wide. The Flutter version drew it about one space wide.
    • Font sizes are whole pixels. 10 points is 13.33 pixels, drawn at 13 pixels with a 13 pixel line.
    • Fonts. The font lists name Windows fonts first. Where one is missing the app falls back to Liberation, DejaVu or the engine's own font. The Windows fonts were not tried on Windows.
    • Double-click on the caption maximizes the window by the engine's own double-click flag. It was tested with simulated clicks, not with a real mouse.
    • Moving and resizing are handed to the window manager. Under Xvfb there was none, so they were only tested with fakes.
    • UTF-16 text in Chinese, Japanese or Korean without a byte order mark has too few zero bytes to be recognised. Choose Unicode in the Open dialog.
    • Large documents are edited through a window of lines. A file made of enormous lines is still slow to edit, and with word wrap on the scroll bar thumb is an estimate (see Large documents).
    • Not verified: Windows, macOS, Linux arm64, a real screen reader, a real printer, Wayland, and every CI and release workflow.
    • Unchanged from the Flutter version: no autosave, backup or recovery; the caption buttons cannot be reached with Tab (the window menu is the keyboard route).

    Getting started

    Requirements

    Verified at runtimeLinuxDeveloperGetting started

    • Godot 4.7.2, the standard build (not the .NET build). The project file asks for 4.7. tools/install_godot.sh downloads it.
    • To use the installer script: curl, unzip and sha512sum, on Linux x86-64 or arm64. On Windows use tools/install_godot.ps1 (not run).
    • A display. The app needs one to run; the tests and the importer run headless.
    • For screenshots only: xvfb-run (Xvfb) with a software OpenGL driver such as Mesa llvmpipe.
    • For exporting only: the export templates for 4.7.2 (tools/install_godot.sh <folder> --templates).
    • Optional: Liberation or DejaVu fonts on Linux, which the font fallbacks use (see Troubleshooting).

    Installation

    Verified at runtimeLinuxGetting started

    Nothing of version 0.2.0 is published yet. The v0.1.1 pre-release is the Flutter version (an arm64 Flatpak). To use 0.2.0, build it from source. release.yml is set up to build a Linux tarball, a Flatpak and a Windows installer for each architecture when a version tag is pushed, but it has never run, so treat those files as untried until a release exists. They are not code-signed, so Windows may show a SmartScreen warning.

    Install Godot 4.7.2 into a folder you choose. The script checks each download against the SHA-512 sums in tools/godot-4.7.2.sha512 and stops on a mismatch; it leaves the editor as <folder>/godot.

    tools/install_godot.sh ~/godot             # the editor, as ~/godot/godot
tools/install_godot.sh ~/godot --templates # and the export templates

    Then export the app (see Build and release) or run it from the project folder (next item). The Linux x86-64 export in build/linux-x86_64/xp_notepad is one self-contained executable of about 74 MB, because it carries the engine.

    Run from source

    Verified at runtimeLinuxDeveloperGetting started

    The first run, and the first run after a script with a new class_name is added, needs the editor's import to register the script classes (tools/run_tests.sh does it for you). After that start the app from the project folder. A file can be passed after --. The exported executable takes the file as its first plain argument. In this pass the import and the exported form with a file were run; godot --path . itself was not started as such, but the screenshot and benchmark tools instantiate the same main scene (src/main.tscn) under Xvfb.

    Set GODOT to the executable if it is not godot on the path; tools/run_tests.sh and tools/shoot.sh read it. A file that does not exist gives the same Cannot find message as File > Open.

    First launch

    Verified at runtimeGetting started

    A new install opens one window titled Untitled - Notepad, centred on the screen. It is 600 by 404 logical pixels, the menu bar is visible, the editor is empty and word wrap is on, so the status bar is hidden. Sizes are logical pixels: the content is scaled by the screen's scale factor and the window is made as many device pixels. The settings file is written when a setting changes and when you exit; none exists before that.

    Where the settings are

    Verified at runtimeGetting started

    • Linux: $XDG_CONFIG_HOME/xp_notepad/settings.json, or ~/.config/xp_notepad/settings.json when XDG_CONFIG_HOME is unset, empty or not an absolute path.
    • Windows: %APPDATA%\xp_notepad\settings.json, falling back to %USERPROFILE% (tested with injected variables; never run on Windows).
    • With no usable folder at all, settings are not kept and nothing is written to the working folder.
    • To reset the settings, close the app and delete the file. Documents are not affected.
    • The file is the same one the Flutter version wrote, with the same keys, so an existing file keeps working. Keys and defaults are listed under Settings, defaults and what they do.

    The annotated figure marks the parts of the window. The status bar appears only when word wrap is off.

    Quick-start tutorial

    Verified at runtimeGetting started

    1. Type a line of text.
    2. Choose Format > Word Wrap to turn wrapping off. The status bar appears and shows Ln 1, Col 1.
    3. Choose File > Save As.... Pick a folder, type a name, leave the encoding as ANSI for plain text, and press Save.
    4. Press Ctrl+F, type a word and press Enter. The match is selected; if there is none, the message Cannot find appears.
    5. Choose View > Dark Mode. The choice is remembered.
    6. Press Ctrl+P. A PDF opens in your PDF viewer; print it from there.
    7. Choose File > Exit. If the text changed you are asked whether to save.

    User manual

    Typing, Tab, Undo and Time/Date

    Verified at runtimeEditing and text

    • Type normally. Enter starts a new line. Tab inserts a tab character (it replaces a selection), drawn 8 columns wide. The Flutter version drew it about one space wide. When printed, a tab goes to the next stop 8 columns apart.
    • Backspace and Delete remove text. Ctrl+A selects everything; Del or Edit > Delete removes a selection.
    • Ctrl+Z or Edit > Undo takes back the last edit. Alt+Backspace also undoes. In a normal document the steps are those of the engine's text control; in a large document the app keeps its own list (see Large documents).
    • The Insert key does not switch to overtype. Ctrl+Insert copies, Shift+Insert pastes and Shift+Delete cuts.
    • F5 inserts the time and date at the caret, for example 3:31 PM 10/7/2026 (en-US form, local time, no seconds; midnight and noon are 12).

    Cut, Copy and Paste

    Verified at runtimeEditing and text

    Ctrl+X, Ctrl+C and Ctrl+V work through the Edit menu and the keyboard. Cut and Copy are enabled only with a selection. Paste is enabled only when the clipboard holds text; the state is read again each time a menu opens. Pasted text has its line ends changed to LF. The round trip through the view model is tested; text copied to and pasted from another program was not tried. Without a display (the headless tests) the clipboard is a variable inside the app.

    Find and Find Next

    Verified at runtimeEditing and text

    Press Ctrl+F. The Find dialog stays open while you edit: it is modeless, and clicking into the text moves the focus there. The Find what box starts with the last search text selected, or with the selected text when the selection does not span lines, so typing replaces it. Type the text and press Enter or Find Next. The search starts at the end of the selection (or the caret) and moves down; choose Up in the Direction group to search upward (the arrow keys move between Up and Down). The search does not wrap: when nothing is left, the message Cannot find "text" appears and focus returns to the Find box.

    F3 repeats the last search without opening the dialog, and opens the dialog when there has been no search. Edit > Find Next is disabled until a search was made. Match case and Match whole word only change which matches count; a word character is a letter, a digit or an underscore. Escape closes the dialog while focus is inside it.

    Replace and Replace All

    Verified at runtimeEditing and text

    Press Ctrl+H. Type the text to find and the replacement. Replace changes the selected match when the selection is exactly a match, then moves to the next one. Replace All changes every match in the document in one step and shows the Cannot find message when there are none; one Ctrl+Z takes the whole replacement back (checked for a small document in this pass, and by tests for a large one). The Replace dialog has no Direction group and always searches down, so an earlier Find upward cannot make Replace search upward unseen (F-17). Nothing happens while the Find what box is empty.

    Go To Line

    Verified at runtimeEditing and text

    Ctrl+G works only with word wrap off, and the Edit menu item is disabled otherwise. The box shows the current line, selected, so typing replaces it; it accepts only digits. Press Enter or Go To. Numbers outside the document go to the first or last line, and a number longer than 15 digits goes to the last line. An empty box keeps the dialog open.

    Word Wrap and the status bar

    Verified at runtimeSettings and view

    Format > Word Wrap toggles wrapping. With wrap on, the status bar is hidden and Go To is disabled. With wrap off, a horizontal scroll bar appears when a line is wider than the window, and View > Status Bar can show or hide the bar, which displays the caret position as Ln n, Col n. The column counts UTF-16 units, as XP does, so a character beyond U+FFFF (an emoji) takes two columns. Both settings are remembered.

    Font

    Verified at runtimeSettings and view

    1. Choose Format > Font....
    2. Pick a family and a style from the lists, or pick a size from the list. The families are Arial, Comic Sans MS, Courier New, Georgia, Impact, Lucida Console, Lucida Sans Unicode, Microsoft Sans Serif, Palatino Linotype, Tahoma, Times New Roman, Trebuchet MS and Verdana. A family that is not installed is drawn with a fallback font. The styles are Regular, Italic, Bold and Bold Italic.
    3. To type a size, select the Size box, type the value and press OK. OK uses the typed size (F-01). Enter in the Size box also applies it to the list and the sample.
    4. Sizes from 1 to 1638 points are accepted. A size outside that range keeps the dialog open with the message Enter a size from 1 to 1638 points. The family list has keyboard focus when the dialog opens, and the arrow keys move through it (F-02).
    5. The Script box is greyed out. It has one entry, Western, and choosing a script was never implemented (F-16).
    6. Sizes are points at 96 DPI, drawn at whole pixels: 10 points is 13.33 pixels and is drawn at 13. The default Lucida Console 10 points has a 13 pixel line, as in XP; other fonts use their own line height.

    Dark Mode

    Verified at runtimeSettings and view

    View > Dark Mode switches the window to the dark palette. The choice is saved and restored at the next launch (the window starts dark when the saved settings say so).

    Page Setup and margins

    Verified at runtimeFiles, encodings and saving

    Header (default &f, the file name), Footer (default Page &p) and four margins in inches, each 0 to 6. The paper is always US Letter (8.5 by 11 inches); there is no paper size or orientation setting. Left plus right must leave at least one inch, and top plus bottom must leave at least one inch. Otherwise the dialog stays open and says so: The left and right margins leave no room to print., The top and bottom margins leave no room to print., Each margin must be from 0 to 6 inches. or, for a box that is not a number, Enter each margin as a number of inches. Enter in any box accepts the dialog when the values are valid (F-06).

    A header or footer accepts &f (file name), &p (page number), &d (date, 10/7/2026 form), &t (time, 3:31 PM form), &l, &c and &r (align the text after it left, centre, right) and && (an ampersand), in upper or lower case (F-24). Text is centred until a code says otherwise. An & followed by anything else is kept as typed.

    Print

    Verified at runtimeFiles, encodings and saving

    Ctrl+P or File > Print... does not open a print dialog, because Godot has no printing of its own. The app lays the text out as a PDF, writes it to its cache folder and opens it in the system's default PDF viewer with OS.shell_open. You print from the viewer, which has the page range, copies and printer choice.

    • Paper: US Letter, 612 by 792 points. Text is set in Courier 10 points and the header and footer in Courier 9 points; the font is one every PDF viewer has, so nothing is embedded. With the default margins a page holds 54 lines of up to 84 columns.
    • Lines are broken at the column limit whatever the Word Wrap setting: after the last space that fits, or in the middle of a word when there is none. Tabs go to stops 8 columns apart, so tab-separated columns line up.
    • The PDF is written as Windows-1252, so a character that ANSI cannot hold prints as ?.
    • The file is <cache folder>/xp_notepad/print/<document name>-<number>.pdf. On Linux the cache folder is ~/.cache (seen in this pass), or $XDG_CACHE_HOME when that is set (from the engine's documentation; not tried); elsewhere it is whatever OS.get_cache_dir() returns (not run on Windows). PDFs of earlier prints that are more than 24 hours old are deleted when you print again.
    • A document of more than 256 Ki characters (262,144) is laid out on a worker thread so the window keeps responding.
    • If the Page Setup margins leave no room (possible only from a damaged settings file), the default margins are used for the margins and the header and footer are kept.

    Verified: the layout by tests (test_print_text.gd, which builds PDFs with every kind of header code) and, in this pass, by running the print service once with the viewer replaced by a stub: 130 lines gave a 3-page Letter PDF, pdfinfo read it, pdftotext showed 54 lines on page 1, the file name as the header and Page n with the date in the footer, and a snowman printed as ?. Not verified: opening the file in a real viewer, a real printer, and the thread path for a long document (no test names the print service). When writing or opening the file fails the message is Notepad cannot print the document.; the file, if it was written, stays in the folder above.

    Opening files

    Verified at runtimeFiles, encodings and saving

    1. Choose File > Open... or press Ctrl+O. If the text changed, answer the save prompt first.
    2. Use Look in, Up and the list to find the file. Folders come first, then matching files, each sorted by name without regard to case; names that start with a dot are not listed. A double-click, or Enter on a selected row, opens a file or enters a folder. Typing the name of a listed folder, or the path of a folder, and pressing Enter opens that folder. A start folder that has been deleted falls back to the nearest folder above it that exists; a folder that cannot be read says This folder cannot be opened. and why.
    3. Files of type offers Text Documents (*.txt) or All Files (*.*).
    4. Typing a path and pressing Enter opens that file. A missing file shows Cannot find "name". Make sure the path and file name are correct.; another failure shows Cannot open "name". and the reason the system gave.
    5. Encoding starts on Detect automatically. Choose ANSI, Unicode, Unicode big endian or UTF-8 to read the file as that encoding instead, which is for files that cannot be told apart, such as UTF-16 Japanese text with no byte order mark (F-14). A byte order mark in the file still wins. The file is saved in the encoding it was opened as.
    6. A file on the command line opens at startup, for example xp_notepad notes.txt. It is read with detection, as if Encoding were left alone, and the title shows its name. The dialogs remember the last folder.
    7. Limits: a folder, a named pipe, a socket or a device such as /dev/zero is refused with a reason; a file of more than 64 MB is refused (The file is too large. Notepad opens files up to 64 MB); a file of more than 16 Mi characters (16,777,216) asks first (see Large documents).

    Saving and Save As

    Verified at runtimeFiles, encodings and saving

    1. Ctrl+S saves to the current file. An untitled document goes to Save As.
    2. Save As: Save in chooses the folder; File name takes the name. If the name has no extension and Text Documents is selected, .txt is added. A folder path typed into the box opens that folder; it is not saved as a file (F-08).
    3. Encoding offers ANSI, Unicode (UTF-16 LE), Unicode big endian and UTF-8, and starts on the document's current encoding (ANSI for a new document).
    4. An existing file other than the current one prompts name already exists. and Do you want to replace it?; answer No to keep it.
    5. If the file cannot be written, the message is Cannot save "name" in "folder". followed by the reason the system gave, such as Permission denied (F-12).

    Encodings and line endings

    Verified at runtimeFiles, encodings and saving

    When a file is opened, a byte-order mark decides UTF-16 or UTF-8, and it wins over everything else, as in XP. Without a mark, UTF-16 is recognised from its zero bytes: Latin and Cyrillic text has a zero in the high byte of most characters, so in the first 4096 bytes the zeros sit at every other place, all odd (little endian) or all even (big endian), and the rest reads as well-formed text with no control characters that a text file never has. The other bytes at those places must be small too (the high bytes of letters of an alphabetic script, up to 0x2B, or surrogate halves), so ASCII text with a NUL here and there, such as the output of find -print0, is not taken for UTF-16. A file with zeros at both kinds of place (UTF-32, binary data), with a stray zero or two, or with a lone surrogate is left alone. Otherwise, valid UTF-8 that contains non-ASCII bytes is read as UTF-8, and everything else as ANSI (Windows-1252). UTF-16 text in Chinese, Japanese or Korean has hardly any zero bytes and cannot be recognised this way; choose its encoding in the Open dialog's Encoding list (F-14).

    Files are saved with CRLF line endings and shown with LF. UTF-16 and UTF-8 are saved with a byte-order mark, ANSI without one. A damaged final byte in UTF-16 shows as the replacement character U+FFFD, and so does each byte of a file read as UTF-8 that is not well-formed.

    Differences from the Flutter version. A Godot string can hold neither a NUL nor a lone surrogate, and the engine's own decoders stop at a NUL. Each NUL byte or UTF-16 unit zero is therefore read as a space (Windows Notepad also shows a NUL as a space), and a lone UTF-16 surrogate is read as U+FFFD. Saving the document writes the space or U+FFFD, not the original, so a file with such characters is changed by an open and save.

    Saving to ANSI characters that ANSI cannot hold

    Verified at runtimeFiles, encodings and saving

    ANSI covers Windows-1252. Saving text that contains other characters asks first, with the XP wording: This file contains Unicode characters which will be lost if you save this file in the ANSI encoding. To keep these characters, click Cancel, and then select one of the Unicode options in the Encoding drop down list. Continue? OK saves with a question mark for each character ANSI cannot hold. Cancel leaves the file unchanged. Characters such as é and € are kept in ANSI.

    Unsaved changes

    Verified at runtimeFiles, encodings and saving

    New, Open and Exit (and closing the window) ask The text in the Untitled file has changed. Do you want to save the changes? with Yes, No and Cancel when the text has changed. No discards and Cancel keeps the document. Yes saves first, or opens Save As for untitled text; if that is cancelled nothing is discarded. Typing during a save keeps the document marked as changed.

    Before you overwrite, replace or discard data

    Verified at runtimeFiles, encodings and saving

    Read this before you save, replace or discard text. The app has no autosave, backup or recovery.

    • Save and Save As replace the file through a temporary file (F-13). An interrupted save leaves the old file whole, though a crash can leave a hidden .name.<pid>.<n>.tmp file beside it. The file's permission bits are kept and are set while the new file is still empty (F-36), and symbolic links are followed so the link itself is kept. A folder that cannot take a temporary file gets the bytes written in place, the one case that is not atomic. Keep copies of important files.
    • Save As asks before it replaces an existing file. Answer No to keep the file.
    • New, Open and Exit discard unsaved changes if you answer No. The discard is final. Cancel keeps the document.
    • Saving to ANSI replaces characters ANSI cannot hold with a question mark. Cancel at the warning keeps the file unchanged.
    • Opening and saving a file with NUL characters or lone UTF-16 surrogates changes them to spaces and U+FFFD (see Encodings and line endings).
    • Replace All changes every match in the document. One Undo takes it back.
    • Text typed while a file opens is kept (F-05). When the file has loaded, a prompt asks whether to save the typed text before the file replaces it.
    • Deleting the settings file resets preferences only. Documents are not affected. Close the app first.

    Dialogs, Escape and focus

    Verified at runtimeDialogs and messages

    Dialogs are drawn inside the main window, not as separate operating-system windows, and only one modal dialog is open at a time; one that is ready while another is open waits its turn. Find and Replace are modeless. A dialog can be dragged by its title bar but never so far that the title bar is out of reach (F-20). Closing the window is ignored while a modal dialog is open. Dialogs take keyboard focus when they open, so typing goes to them and not to the document (F-02). Find returns focus to its box after a message (F-03). Escape cancels the dialog that has focus, and closes an open list in a combo box first. Menus close when the window loses focus.

    Using the menus from the keyboard

    Verified at runtimeKeyboard and menus

    Press Alt with the underlined letter to open a menu, for example Alt+F for File. The underlines appear when Alt is tapped. Press the letter of an item to run it. Up and Down move the highlight, Left and Right change menus, Enter runs the highlighted item, and Escape closes the menu. Menu items that are disabled are skipped. A lost Alt key-up (after Alt+Tab, say) does not turn later plain letters into menu commands, and Ctrl+Alt, which is how Windows reports AltGr, types its character instead of opening a menu (F-32).

    The window menu

    Verified at runtimeKeyboard and menus

    Press Alt+Space, click the small icon at the left of the caption, or right-click the caption to open the window menu, as in XP. It lists Restore (enabled when the window is maximized), Move and Size (greyed out: the window manager moves and resizes the window, from the caption and the edges), Minimize, Maximize and Close (Alt+F4). Up, Down, Enter, the underlined letters and Escape work as in the other menus; Right goes on to the File menu and Left to the Help menu; Alt+Space again closes it. Together with Alt+F4 and File > Exit this gives the keyboard a way to every window command, which the caption buttons do not (F-19). The caption buttons themselves still cannot be reached with Tab. Alt+Space does nothing while a dialog is open. The icon is named Window menu for assistive technology.

    Large documents

    Verified at runtimeEditing and text

    The engine's text control shapes every line it holds, which costs about 2.5 s and 277 MB for a 1 MB document and 9 s and 1.2 GB for 5 MB. A document of 131,072 characters (128 K) or more is therefore edited through a window: the control holds the lines around what is on screen, a few hundred lines, and a scroll bar for the whole document stands in for its own. Nothing has to be done for this. The scroll bar and the mouse wheel cover the whole document, and Find, Replace All, Go To, Save, Print and the status bar work on the whole text.

    Measured with tools/bench_large.gd under Xvfb with software rendering (llvmpipe), word wrap on. A typed character costs two frames at every size. Without the window, the engine's control took 2.5 s and 277 MB at 1 MB and 9 s and 1.2 GB at 5 MB. Absolute times differ from machine to machine and from run to run: a re-run in this pass gave 67 ms and 232 ms to load 1 MB and 5 MB, 61 MB and 95 MB of memory, and 33.3 ms for a typed character.

    • Ctrl+Home and Ctrl+End go to the start and the end of the whole document, and with Shift they select up to there. Select All selects everything, and typing over it replaces the whole document.
    • Undo (Ctrl+Z, Alt+Backspace or Edit > Undo) takes back typing, deleting and pastes in the whole document. Text typed within about 0.6 s joins into one step. The list holds up to 200 steps, and no more than 16 Mi characters of text.
    • A key typed while the caret is out of sight scrolls back to the caret first, so the text goes where it was left.
    • A document that grows past the limit, by a paste for example, switches to this mode, and the paste can be undone. It keeps its window if it shrinks again, until another document is opened or New is chosen.

    Limits: the window holds whole lines, so a line of many tens of thousands of characters is laid out whole, and a file made of enormous lines (minified JSON, say) is slow to edit, in proportion to the length of the line. Building the whole text, as Save, Print and Find do, takes time in proportion to the size (2.1 s at 60 MB) and is then kept until the next edit. With word wrap on, the size and place of the scroll bar thumb are estimates, because lines wrap to different heights; the text on screen stays where it is. A screen reader is told only the lines in the window. The window does not move while a mouse button is held in the text, so a selection that is being dragged is not disturbed; that was tested with simulated pointers, and a long drag with a real mouse has not been tried.

    Startup sequence

    Verified at runtimeArchitecture

    1. Godot loads project.godot: the main scene is src/main.tscn, a single Node with main.gd. The window is borderless, 600 by 404, with the Compatibility renderer and low-processor mode (the app idles when nothing changes), capped at 60 frames per second.
    2. Main._ready builds the dependencies (AppDependencies.standard) and loads the settings.
    3. The content scale factor is set to the screen's scale (at least 1), the minimum size to 400 by 310 logical pixels and the size to the saved one, and the window is centred.
    4. NotepadViewModel.new sets the palette and builds the text control with the saved font and wrapping; NotepadScreen.new is added to the tree.
    5. view_model.start(path) connects the window events, prevents the window from closing without the app's say, sets the title, refreshes the clipboard state and opens the command-line file by the same code path as File > Open, without the save prompt (nothing is open yet).
    6. The file comes from the first plain argument after -- and, in an exported app only, from the first plain command-line argument.

    State management and commands

    Verified at runtimeArchitecture

    • The view model is a RefCounted object that emits changed. The screen redraws from it in one _refresh(): caption, menus, status bar, find dialog, modal host and popup.
    • A command that asks the user something is a coroutine and is awaited: _show_modal(request) sets the open dialog, emits changed and waits for request.result(). The tests start a command, answer what it asks and collect the result (test/support/pending.gd).
    • A counter, _document_request, is moved on by every New and Open, so a read that finishes after a newer request is dropped and cannot replace what the user chose since. A second save while one runs returns false.
    • The document counts as modified when the text control's edit count differs from the count at the last open or save. The count is exact at once, where the control's own change signal comes a step late.
    • Settings are values with copy_with; each change replaces the settings and saves them.
    • Failures are Result objects (ok, value, error) holding a FileError. Callers handle both cases.
    • Shortcuts are handled in NotepadScreen._shortcut_input (Ctrl+N, O, S, P, F, H, G and F1, F3, F5), menu and Alt keys in _input, and editing keys in XpTextEdit. Editing shortcuts yield to a focused dialog text box, and nothing runs while a modal dialog is open.

    Data flow: File > Open

    Verified at runtimeArchitecture

    1. open_document checks for unsaved changes first.
    2. The Open dialog answers with a FileChoice. Its open_as holds the encoding chosen in the Encoding list, or DETECT (F-14).
    3. _open_path calls documents.read and records a request number; a result is dropped if a newer New or Open has started.
    4. read_bytes refuses a folder, a pipe or a socket and reads in 1 MiB chunks up to 64 MB; read_text takes the encoding from a byte-order mark, else from the choice, else by detection. Files over 512 KB are decoded on a worker thread (WorkerThreadPool) while the window keeps running.
    5. On success the document is replaced, the file's folder becomes lastDirectory, and the text goes to XpTextEdit.load_document, which switches to a window of lines from 128 Ki characters. On failure a message is shown.
    6. Edits typed while step 3 ran are detected, and the save prompt is shown before the file replaces them (F-05). The text the user agreed to lose at the first prompt is remembered, so answering No does not lead to a second prompt (F-29).
    7. A document of more than 16 Mi characters asks first. A question or message that is ready while another dialog is open waits its turn, and is dropped only if the open it belongs to has been replaced meanwhile (see Modal dialogs).

    Data flow: save

    Verified at runtimeArchitecture

    1. Save or Save As asks for a path; a path other than the current one that already exists asks to replace it.
    2. A save to ANSI with characters ANSI cannot hold asks first.
    3. TextCodec.encode_text writes CRLF and the byte-order mark for the chosen encoding; text over 512 Ki characters is encoded on a worker thread.
    4. The bytes go to a temporary file beside the document (.name.pid.n.tmp), whose permission bits are set to those of the old file while it is still empty (F-36), and the temporary file is then renamed over the document (F-13). A symbolic link is followed so the link is kept. A refused rename is tried again after short pauses (50, 150, 300 and 500 ms) on Windows only, where a virus scanner can hold a file for a moment. A folder that cannot take a temporary file gets an in-place write, the one case that is not atomic.
    5. The document is marked clean only if nothing was typed during the write.

    Modal dialogs

    Verified at runtimeArchitecture

    Each dialog is a DialogRequests.Request subclass that is answered once with complete(value); a null answer means cancelled. The view model sets _modal and waits for the answer. While a request is open, a second one waits in a queue (Turn objects) and is shown when the first closes, so an error found while About is open is shown after it, not dropped (the Flutter version counted a dropped dialog as the answer No). A question asked after a wait, such as the large-file question and the save prompt after a read, passes still_wanted: when its turn comes and the open it belongs to has been replaced meanwhile, it is not shown. ModalDialogHost picks the dialog class for the request type and shows it inside the window, centred over a barrier that keeps clicks from reaching the text. Find and Replace are not requests: the view model holds a FindState and the screen shows a modeless FindDialog.

    Custom-drawn controls and the theme

    Confirmed in sourceArchitecture

    • The Luna look is drawn by the app: the window frame and caption (the window is borderless), menu bar and popups, buttons, check and radio boxes, group boxes, list and combo boxes, the status bar and the dialog window are controls of src/ui/core/ that paint themselves in _draw() with XpDraw, XpGradients and XpColors. XpIcons draws the Notepad icon in code. No image files are used for the interface.

    The editor: XpTextEdit

    Verified at runtimeArchitecture

    • XpTextEdit extends the engine's TextEdit, which does the editing, undo, caret, selection, scrolling and wrapping. The class adds what is particular to Notepad: Tab types a tab character, Insert does not switch to overtype, Alt+Backspace undoes, Ctrl+Insert, Shift+Insert and Shift+Delete copy, paste and cut, text is pasted with LF line ends, the tab stop is 8, selected text is drawn white over the highlight, and the context menu, middle-click paste and drag and drop are off.
    • Everything outside the class asks its document methods (document_text, caret_document_line, select_offsets, go_to_document_line, replace_document and so on), which answer for the whole document whether or not it is windowed.
    • XpEditor frames the control (the white, bordered area) and draws the corner where the two scroll bars meet, and shows the scroll bar of the whole document in place of the control's own while a document is windowed.

    Editing large documents

    Verified at runtimeArchitecture

    The engine's TextEdit shapes every line it holds: about 2.5 s and 277 MB for a 1 MB document and 9 s and 1.2 GB for 5 MB. A document of 128 Ki characters (XpTextEdit.LARGE_DOCUMENT_CHARACTERS, 131,072) or more is therefore held by a LargeDocument, and the control holds only a window of it.

    • The window is built about WINDOW_CHARS = 100,000 characters wide, centred on the target line. It is extended by CHUNK_CHARS = 40,000 when the view comes within about 60 lines (or two screens, if that is more) of its edge, and the end farthest from the view is dropped when it passes MAX_WINDOW_CHARS = 220,000 or MAX_WINDOW_LINES = 4,000 lines.
    • Edits made in the control are copied into a shadow of the window and into the EditHistory as changes of whole lines, so undo survives the window moving. Typing and deleting one character at a time (up to 64 characters) within 600 ms join into one entry; a paste never joins. The list is limited to 200 entries and 16 Mi characters, oldest first.
    • A selection bigger than the window (Select All, Ctrl+Shift+End) is kept as a wide selection of document positions; typing, Delete or Enter replaces all of it, and moving the caret ends it.
    • Ctrl+Home and Ctrl+End are handled by the app because the control moves only within its window. A click ends a wide selection. A key typed while the caret is outside the window first brings the window back to it.
    • The version of a windowed document is kept by LargeDocument and never goes back, so the modified state stays right when the window is rebuilt or the document shrinks.
    • The whole text (full_text()) is joined on demand and cached until the next edit, so repeated Find Next does not join it again. This is the 2.1 s at 60 MB.
    • Typing is not tied to the document size: one typed character costs the engine two frames, about 33 ms, at every size tried. A fuzz test (test_large_document.gd) runs random edits, scrolls, selections and undos against a plain string and compares both after every step.

    Accessibility

    Verified at runtimeArchitecture

    • Godot 4.7 passes an accessibility tree to the platform through AccessKit. The engine's own controls (the text editor, the text boxes, labels and scroll bars) describe themselves; the text editor is named Text editor and each text box has an accessible name such as Find what.
    • The app's own controls, which are drawn rather than built from engine controls, describe themselves through src/ui/core/xp_accessibility.gd. Each has an accessibility_info() that returns a dictionary: role (button, default button, check box, radio button, menu bar, menu, menu item, check menu item, list, list option, dialog, region, group, title bar, text), name, and as needed value, checked, selected, disabled, expanded, modal, alert, shortcut, action (what a click by assistive technology runs) and children (the rows of a list or a menu). On NOTIFICATION_ACCESSIBILITY_UPDATE the control passes it to XpAccessibility.apply, which writes it into the engine's tree with DisplayServer.accessibility_update_set_*.
    • Updates are requested only while a screen reader is active (DisplayServer.accessibility_screen_reader_active()), so the cost is nothing otherwise.
    • While a modal dialog is open the host registers itself as modal_root, and every control outside it is flagged hidden, as the window behind a dialog is. A message box is flagged an alert, which the reader announces at once.
    • The icon of the title bar is a button named Window menu; the caption buttons are named buttons; the status bar says the line and column; the menu bar says which menu is open; the highlighted menu item is the selected one.
    • test/ui/test_accessibility.gd (24 tests) walks the whole window and checks what each control reports: names, roles, states, shortcuts, hiding behind a dialog, and that pressing a button or a menu by assistive technology does the same as a click. It checks the dictionaries the controls hand over; it does not check what AccessKit sends to the platform, and no screen reader has been tried. In a large document the editor's text is the window of lines, so a reader is told only those.

    Concurrency and performance

    Confirmed in sourceArchitecture

    • The app is single-threaded except for three jobs given to WorkerThreadPool while the window waits frame by frame: decoding a file over 512 KB, encoding text over 512 Ki characters for a save, and laying out a PDF over 256 Ki characters. A save waits for its thread without blocking the window, and one save runs at a time.
    • A resize is acted on 0.15 s after it stops, so a drag does not save the settings or move the window at every step.
    • The folder list examines each entry one after another on the main thread. It sorts on a lower-case key made once per entry and skips files the type filter hides before looking at them (F-38).
    • The renderer is the Compatibility one, and the app idles when nothing changes (low-processor mode, 60 frames per second at most).

    Error handling

    Verified at runtimeArchitecture

    • GDScript has no exceptions, so a file operation returns a Result. A FileError carries the system's own wording when it gave one (Permission denied, No such file or directory, ...) and the view model puts it in the message after the file name (F-12). When there is no usable reason the line is left out.
    • A missing file has its own XP wording; any other reason is told as it is. A failed save says where and why and leaves the old file. A failed settings save is ignored, because settings are a convenience and must not block editing or closing.
    • A settings file that cannot be read gives the defaults; a value of the wrong type falls back to its default.

    Window control

    Confirmed in sourceArchitecture

    • WindowService is the interface (title, size, minimize, maximize, close, drag, resize, signals for close, focus, maximize and resize); GodotWindowService implements it on the main Window, with sizes in logical pixels (the window size divided by the content scale). Tests use FakeWindowService.
    • The window is borderless. The caption starts a drag with DisplayServer.window_start_drag after a 4 pixel movement, and the frame bands and the size grip start a resize with window_start_resize; the window manager does the rest.
    • Closing is intercepted (auto_accept_quit is turned off), so the app can ask about unsaved changes. The window cannot close while a dialog is open.
    • A Linux window manager can let an edge drag go below the minimum, so the app holds the minimum itself 0.15 s after a resize, and remembers the last normal (not maximized) size to save at exit.

    Security and privacy boundaries

    Confirmed in sourceArchitecture

    • The app has no network code, no telemetry and no update check. It reads files you open and writes files you save, the settings file, and print PDFs in the cache folder.
    • It starts one other program: the system's default PDF viewer for Print, through OS.shell_open. It also runs sh -c 'test -p "$1" || test -S "$1"' to ask whether a path is a named pipe or a socket before opening it, because opening a pipe would wait for a writer for ever. The path is passed as an argument with execute_with_pipe, not put in the command, so a file name with a quote or a dollar sign runs nothing (tested). This is not done on Windows.
    • A save keeps the permission bits of the file it replaces, set before the text is written (F-36). Print PDFs are written with the default permissions of the cache folder.
    • This handbook loads nothing from the network.

    Conventions

    Confirmed in sourceDeveloperDevelopment and tests

    • Typed GDScript; one class per file with a class_name; ## doc comments that explain intent, in the style of the existing code. Tabs for indentation.
    • The .gd.uid files that Godot 4.4 and later writes for each script are committed (130 of them). .godot/ (the import cache) and build/ are ignored.
    • The domain layer holds no nodes. The view model holds no nodes except the text control. Services are reached through AppDependencies, so a test can replace them.
    • No formatter or linter is run by the repository. test_scripts_compile.gd loads every script, so a parse error fails the suite.
    • A test names the finding it guards; the version check in test_app_info.gd fails when the files that repeat the version disagree.

    The release workflow

    Confirmed in sourceMaintainerBuild and release

    .github/workflows/release.yml runs when a tag that starts with v is pushed, or by hand (workflow_dispatch, which builds the files as workflow artifacts and creates no release). Jobs, in order:

    1. Check version: reads config/version from project.godot and, for a tag, fails unless the tag is v plus that version.
    2. Export with Godot (one Ubuntu job, because Godot exports every platform from Linux): runs the tests, exports the four executables, checks the machine type of each with a short Python script (PE 0x8664 and 0xAA64; ELF 62 and 183) and uploads them.
    3. Linux (x64 on ubuntu-24.04, arm64 on ubuntu-24.04-arm): packs xp-notepad-<version>-linux-<arch>.tar.gz (the executable, LICENSE and README.md) and builds a Flatpak bundle with packaging/flatpak/build.sh.
    4. Windows (x64 on windows-latest, arm64 on windows-11-arm): installs Inno Setup with Chocolatey and compiles packaging/windows/xp-notepad.iss to xp-notepad-<version>-windows-<arch>-setup.exe.
    5. Publish (tags only): writes SHA256SUMS.txt and creates the GitHub release, or adds the files to an existing one. A tag with a hyphen (such as v0.3.0-rc1) is marked a pre-release.

    The actions are pinned to commit hashes. The files are not code-signed, so Windows may show a SmartScreen warning. The workflow has never run, so every step above is untried in CI, including the Flatpak and Chocolatey steps and the arm64 runners.
