    Overview

    What XP Notepad is

    Verified at runtimeOverview

    XP Notepad is an unofficial recreation of the Windows XP Notepad (Luna blue) written in Flutter for desktop. The window, caption, menu bar, dialogs and status bar are Flutter widgets. The project has no WebView, no HTML, and no native code of its own. It was built and run on Linux during this audit; Windows was not built or run.

    How to use this handbook

    Verified at runtimeOverview

    • Search, filter and read. Use the search box and the five filters. Filters combine: an item must match every filter that is set. Severity applies only to audit findings, so choosing a severity hides everything else.
    • Links. Every item has an anchor. Use the Copy link button beside its heading, or the address bar. A link to a hidden item resets the filters so the item is visible.
    • Screenshots. Select a thumbnail to enlarge it; press Escape to close.
    • Copy. Each command and code example has a Copy button.
    • Print. The print button prints the items currently shown, with the collapsed details opened.

    Quick-start tutorial

    Verified at runtimeGetting started

    1. Type a line of text. If the text does not appear after New or Open, click inside the text first (see F-04).
    2. Choose Format > Word Wrap to turn wrapping off. The status bar appears and shows Ln 1, Col 1.
    3. Choose File > Save As.... Pick a folder, type a name, leave the encoding as ANSI for plain text, and press Save.
    4. Press Ctrl+F, type a word and press Enter. The word is selected. Press F3 for the next match.
    5. Choose File > Exit. If the text changed, answer Yes to save, No to discard, or Cancel to stay.
    6. Expected result: the file holds your text with CRLF line endings. Reopen it to check.

    User manual

    Typing, Tab, Undo and Time/Date

    Verified at runtimeEditing and text

    • Type normally. Enter starts a new line. Tab inserts a tab character, drawn about one space wide on screen. When printed, a tab goes to the next stop eight columns apart (F-24).
    • Backspace and Delete remove text. Ctrl+A selects everything; with a selection, Delete removes it.
    • Ctrl+Z undoes the last typed group. Alt+Backspace also undoes.
    • F5 inserts the time and date at the caret, for example 3:31 PM 10/7/2026 (en-US form, local time).

    Cut, Copy and Paste

    Confirmed in sourceEditing and text

    Ctrl+X, Ctrl+C and Ctrl+V work through the Edit menu and the keyboard, and Ctrl+Insert and Shift+Insert copy and paste. Cut and Copy are enabled only with a selection. Paste is enabled only when the clipboard holds text. The menu states were seen at runtime; the clipboard round trip was not run.

    Find and Find Next

    Verified at runtimeEditing and text

    Press Ctrl+F. The Find dialog stays open while you edit. Type the text and press Enter or Find Next. The search starts at the caret and moves down; choose Up in the Direction group to search upward. The search does not wrap: when nothing is left, the message Cannot find "text" appears.

    F3 repeats the last search. Match case and Match whole word only change which matches count (covered by unit tests; not run interactively).

    Replace and Replace All

    Verified at runtimeEditing and text

    Press Ctrl+H. Type the text to find and the replacement. Replace changes the selected match and moves on (the single Replace button was not run; Replace All was). Replace All changes every match and shows the not-found message when there are none. Replace always searches down; it no longer takes the Direction of an earlier Find, which the dialog does not show (F-17, fixed in 0.1.2).

    Go To Line

    Verified at runtimeEditing and text

    Ctrl+G works only with word wrap off, and the Edit menu item is disabled otherwise. The box shows the current line; type a number and press Enter. Numbers outside the document are clamped to the first or last line. The pre-filled number is selected when the box opens, so typing replaces it (F-09, fixed in 0.1.2). A number too long for an integer goes to the last line (F-34).

    Word Wrap and the status bar

    Verified at runtimeSettings and view

    Format > Word Wrap toggles wrapping. With wrap on, the status bar is hidden and Go To is disabled. With wrap off, View > Status Bar can show or hide the bar, which displays the caret position as Ln n, Col n.

    Font

    Verified at runtimeSettings and view

    1. Choose Format > Font....
    2. Pick a family and a style from the lists, or pick a size from the list.
    3. To type a size, select the Size box, type the value and press OK. OK uses the typed size (F-01, fixed in 0.1.1). Enter in the Size box also applies it to the lists and the sample.
    4. Sizes from 1 to 1638 points are accepted; a size outside that range keeps the dialog open with a message. The family list has keyboard focus when the dialog opens, and the arrow keys move through it (F-02, fixed in 0.1.1).
    5. The Script list is a placeholder (F-16).

    Dark Mode

    Verified at runtimeSettings and view

    View > Dark Mode switches the window to the dark palette. The choice is saved and restored at the next launch.

    Page Setup and margins

    Verified at runtimeFiles, encodings and saving

    Header (default &f, the file name), Footer (default Page &p) and four margins in inches, each 0 to 6. On letter paper, left plus right must leave at least one inch, and top plus bottom must leave at least one inch. Otherwise the dialog stays open and says so. Enter in any box accepts the dialog when the values are valid (F-06, fixed in 0.1.2). A header or footer accepts &f (file name), &p (page number), &d (date), &t (time), &l, &c and &r (align left, centre, right) and && (an ampersand), in upper or lower case (F-24, fixed in 0.1.2). Text is centred until a code says otherwise.

    Print

    Verified at runtimeFiles, encodings and saving

    Ctrl+P lays the text out as a Letter PDF with the Page Setup margins and opens the platform print dialog. On Linux that is the GTK dialog, titled with the file name. It has Print to File and Print to LPR, and a command line. The dialog was opened and closed with Escape. No paper output was produced, so printing is not verified.

    Opening files

    Verified at runtimeFiles, encodings and saving

    1. Choose File > Open... or press Ctrl+O. If the text changed, answer the save prompt first.
    2. Use Look in and the list to find the file. Folders come first, then matching files. Typing the name of a listed folder and pressing Enter opens that folder (run in session S2); double-click was not run.
    3. Files of type offers Text Documents (*.txt) or All Files (All Files not run).
    4. Typing a path and pressing Enter opens that file. A missing file shows Cannot find "name". Make sure the path and file name are correct.
    5. A file on the command line opens at startup, for example xp_notepad notes.txt.

    Saving and Save As

    Verified at runtimeFiles, encodings and saving

    1. Ctrl+S saves to the current file. An untitled document goes to Save As.
    2. Save As: Save in chooses the folder; File name takes the name. If the name has no extension and Text Documents is selected, .txt is added.
    3. Encoding offers ANSI, Unicode (UTF-16 LE), Unicode big endian and UTF-8.
    4. An existing file prompts name already exists. Do you want to replace it?; answer No to keep it.
    5. If the folder cannot be written, the message is Cannot save "name". (F-12).

    Encodings and line endings

    Verified at runtimeFiles, encodings and saving

    When a file is opened, a byte-order mark decides UTF-16 or UTF-8. Without a mark, valid UTF-8 that contains non-ASCII bytes is read as UTF-8, and everything else as ANSI (Windows-1252). Files are saved with CRLF line endings. UTF-16 and UTF-8 are saved with a byte-order mark, ANSI without one. A UTF-16 file without a mark is read as ANSI (F-14, a known limitation: the byte order mark is the only signal, and a guess from the bytes could misread an ordinary file). A damaged final byte in UTF-16 shows as the replacement character.

    Saving to ANSI characters that ANSI cannot hold

    Verified at runtimeFiles, encodings and saving

    ANSI covers Windows-1252. Saving text that contains other characters asks first. OK saves with a question mark for each character ANSI cannot hold. Cancel leaves the file unchanged. Characters such as é and € are kept in ANSI.

    Unsaved changes

    Verified at runtimeFiles, encodings and saving

    New, Open and Exit ask Yes, No or Cancel when the text has changed. No discards and Cancel keeps the document (both run, on New and on Exit). Yes saves first, or opens Save As for untitled text (not run).

    Before you overwrite, replace or discard data

    Verified at runtimeFiles, encodings and saving

    Read this before you save, replace or discard text. The app has no autosave, backup or recovery.

    • Save and Save As replace the file through a temporary file (F-13, fixed in 0.1.1). An interrupted save leaves the old file whole, though a crash can leave a hidden .tmp file beside it. The file's permission bits are kept (they are set while the new file is still empty, F-36) and symbolic links are followed. When a save fails the message says where and why (F-12). Keep copies of important files.
    • Save As asks before it replaces an existing file. Answer No to keep the file (checked).
    • New, Open and Exit discard unsaved changes if you answer No. The discard is final. Cancel keeps the document (checked on New and Exit).
    • Saving to ANSI replaces characters ANSI cannot hold with a question mark. Cancel at the warning keeps the file unchanged (checked).
    • Replace All changes every match in the document. Undo after Replace All was not run; undo was checked after typing and after a replacement of selected text.
    • Text typed while a large file opens is kept (F-05, fixed in 0.1.1). When the file has loaded, a prompt asks whether to save the typed text before the file replaces it.
    • Deleting the settings file resets preferences only. Documents are not affected. Close the app first.

    Files, storage and the settings location

    Verified at runtimeFiles, encodings and saving

    • Documents are plain text files. The app adds no format of its own.
    • Settings file: $XDG_CONFIG_HOME/xp_notepad/settings.json, or ~/.config/xp_notepad/settings.json when XDG_CONFIG_HOME is unset (Linux). On Windows it is %APPDATA%\xp_notepad\settings.json (not run here).
    • An empty XDG_CONFIG_HOME, or one that is not an absolute path, is ignored and HOME/.config is used (F-10, fixed in 0.1.2). With no usable folder at all, settings are not kept and nothing is written to the working folder.
    • Deleting the settings file, with the app closed, restores every default.

    Backup, recovery, import and export

    Confirmed in sourceFiles, encodings and saving

    None of these exists. The source has no autosave, backup or crash-recovery code, and no import or export beyond plain-text Open and Save As. A save replaces the file through a temporary file (F-13, fixed in 0.1.1), but there is still no backup or recovery copy, so keep copies of important files.

    Startup sequence

    Confirmed in sourceArchitecture

    1. main calls windowManager.ensureInitialized and loads settings (lib/main.dart:8-12).
    2. The window is created with the saved content size, a 400 by 310 minimum, a hidden title bar and the title Untitled - Notepad (lib/main.dart:15-27).
    3. runApp(XpNotepadApp) builds the providers. The view model's start attaches window events, prevents close, sets the title and refreshes the clipboard state (notepad_view_model.dart:467-473).
    4. A file path on the command line is opened by the same code path as File > Open, without the save prompt (nothing is open yet).

    State management and commands

    Confirmed in sourceArchitecture

    • The view model is a ChangeNotifier provided with provider. The window rebuilds through ListenableBuilder.
    • Saves run as Command1 objects, where a second save while one runs returns null (lib/utils/command.dart:19-20). Document reads run directly, so a newer New or Open can supersede an older read (notepad_view_model.dart:596-604).
    • Results are sealed Success and Failure values (lib/utils/result.dart). Callers handle both.
    • Settings are immutable models with copyWith. Every change calls the repository and then notifies listeners.
    • Keyboard shortcuts are a Shortcuts and Actions map in notepad_screen.dart:123-183; editing shortcuts yield to a focused dialog text box.

    Data flow: File > Open

    Confirmed in sourceArchitecture

    1. openDocument checks for unsaved changes (notepad_view_model.dart:148-159).
    2. The Open dialog returns a FileChoice (dialog_requests.dart).
    3. _openPath calls documents.read and records a request number; a result is dropped if a newer New or Open has started (notepad_view_model.dart:596-600).
    4. readText detects the encoding and decodes; files over 512 K bytes use Isolate.run (document_repository.dart:20-33).
    5. On success the document is replaced and lastDirectory is saved (notepad_view_model.dart:587-591). On failure a message is shown (notepad_view_model.dart:592-603).
    6. Edits typed while step 3 ran are detected, and the save prompt is shown before the file replaces them (F-05, fixed in 0.1.1).
    7. The text the user agreed to lose at the first prompt is remembered, so answering No does not lead to a second prompt (F-29, fixed in 0.1.2). Only text typed after that asks again.
    8. The read is in chunks and stops at 64 MB, and refuses a folder, a pipe or a socket (F-30, fixed in 0.1.2). A document of more than 2 million characters asks first, because editing it is very slow (F-31).

    Data flow: save

    Confirmed in sourceArchitecture

    1. Save or Save As asks for a path; a path that already exists asks to replace it (notepad_view_model.dart:167-187).
    2. A save to ANSI with characters ANSI cannot hold asks first (notepad_view_model.dart:606-621).
    3. encodeText writes CRLF and the byte-order mark for the chosen encoding (text_codec.dart:74-87).
    4. The bytes go to a temporary file beside the document, which then replaces it (document_repository.dart, _save; F-13, fixed in 0.1.1). Symbolic links are followed and POSIX permission bits are copied. A folder that cannot take a temporary file gets an in-place write, the one case that is not atomic.
    5. The document is marked clean only if nothing was typed during the write (notepad_view_model.dart:641).

    Modal dialogs

    Confirmed in sourceArchitecture

    Each dialog is a ModalRequest subclass holding a Completer. The view model sets _modal and awaits the result; while a request is open, a second one returns null. dialog_host.dart switches on the request type and shows the matching widget inside XpDialogWindow over an XpModalBarrier.

    Persistence

    Confirmed in sourceArchitecture

    Settings are pretty-printed JSON. Each save is queued behind the one before it, written to a temporary file beside settings.json and renamed over it (F-35, fixed in 0.1.2). Write errors are ignored by design so editing continues. With no usable settings folder, nothing is written (F-10). Damaged JSON or wrong types fall back to defaults at load (settings_repository.dart:35-47).

    Concurrency and performance

    Confirmed in sourceArchitecture

    • Files over 512 KB are decoded or encoded in an isolate (document_repository.dart:20, 25-28, 42-44).
    • Dialog lists use ListView.builder (xp_fields.dart:295, file_dialog.dart:355, help_dialog.dart:87).
    • Painters repaint only when their inputs change (shouldRepaint in xp_frame.dart, xp_scrollbar.dart, xp_icons.dart). Since 0.1.2: the PDF for printing is laid out in an isolate (F-39); a folder is examined 64 entries at a time with a sort key made once per entry (F-38); the no-wrap editor measures its longest line once per text, not once per caret move (F-37).
    • The whole document is one text field, so memory grows with the file. Measured here: about 1.6 GB resident for a 4.86 MB file, with the title appearing in about 0.5 to 1.0 s (session S4). The README's figures are from another run. The cost of editing is the larger problem (F-31): Flutter's text input carries the whole text on each change, so in the second pass one typed character took about 0.06 s of processor time at 100 KB, 0.7 s at 1 MB and about 4 s with 2 GB resident at 5 MB, while moving the caret cost about 0.09 s per key at 1 MB.

    Security and privacy boundaries

    Confirmed in sourceArchitecture

    • No network, socket or URL code exists in lib/ (searched for HTTP, socket and URL launch APIs), and the app makes no external requests. The only process it starts is chmod, to copy a file's permission bits onto the new file after a save; it is run directly, not through a shell, with the path after a -- (F-36). The original text of this item said there was no process code; chmod was added with the atomic save in 0.1.1.
    • Files: the app reads and writes only the documents you open or save, and its settings file. It does not scan folders. Each file is read in chunks and refused past 64 MB, and a folder, pipe or socket is refused first, so a device such as /dev/zero cannot exhaust memory (F-30, fixed in 0.1.2). A new file gets its permissions before any text is written.
    • The settings file stores the last folder you used (lastDirectory), so it reveals folder paths. It is plain JSON; keep it private on shared machines.
    • Clipboard: Cut and Copy write the selection to the system clipboard. When a menu opens, the app reads the clipboard text only to decide whether Paste is enabled (notepad_view_model.dart:276-282; notepad_screen.dart:215-220 and 315-331). It does not store or send it.
    • Malformed UTF-8 is decoded with replacement characters rather than failing (text_codec.dart:57).
    • Printing hands the PDF to the platform print dialog (printing plugin). Its behaviour, such as where a file is sent, is outside this code and was not examined.
    • No telemetry, analytics, accounts or credentials. The app runs with the user's own permissions.
